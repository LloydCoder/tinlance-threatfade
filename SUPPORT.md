# ThreatFade Support

Use the channel that matches the request. Do not publish credentials, private keys, customer data, packet captures, or exploit details in public.

## Usage and configuration questions

1. Read the [README](README.md) and [documentation index](docs/README.md).
2. Search [existing issues](https://github.com/LloydCoder/tinlance-threatfade/issues).
3. Open a [GitHub issue](https://github.com/LloydCoder/tinlance-threatfade/issues/new/choose) for a reproducible non-sensitive bug or a feature request.

Include the ThreatFade version or commit, operating system, Python version, deployment mode, relevant sanitized logs, expected behavior, actual behavior, and minimal reproduction steps.

## Installation and deployment support

Consult:

- [Configuration reference](docs/reference/configuration.md)
- [Secure deployment](docs/SECURE_DEPLOYMENT.md)
- [Sensor runtime](docs/SENSOR_RUNTIME.md)
- [Disaster recovery](docs/DISASTER_RECOVERY.md)

The public repository is community-supported. No contractual response time, uptime commitment, managed incident response, or commercial support entitlement is implied by opening an issue.

## Security vulnerabilities

Do not open a public issue for a suspected vulnerability. Follow [SECURITY.md](SECURITY.md) and report privately to **security@tinlance.com**.

## Commercial and enterprise enquiries

For commercial or enterprise enquiries, contact Tinlance Limited through its official website or the contact details published by Tinlance. Do not include sensitive production data in an initial enquiry.
